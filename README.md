# Yabgu: Custom File Encryption Tool

A small command-line tool that encrypts and decrypts files with a seeded, key-driven byte-substitution cipher. Written in C, with no dependencies.

> [!WARNING]
> **Yabgu is a learning project, not secure encryption.** It is fine for keeping files away from casual snooping. Do **not** use it to protect anything sensitive. See [Security](#security) for details.

## Read this before you use it

- **Yabgu deletes the original file after a successful run.** Encrypting `notes.txt` leaves only `notes.txt.yabgu`, and decrypting `notes.txt.yabgu` leaves only `notes.txt`. Work on a copy until you grasp how the tool works.
- **There is no password recovery.** You need the exact **seed and key** you used. If you forget either one, the data cannot be recovered.
- **A wrong seed or key does not produce an error.** Decryption "succeeds" and gives you a garbage file, and the `.yabgu` file is deleted. If this happens, you can undo it: encrypt the garbage file again using the *same wrong* seed and key, and you get the original `.yabgu` file back. This only works if you remember exactly what you typed.
- **Existing files are never overwritten.** If the output file already exists, the program stops and asks you to move or rename it.
- **Interrupting a run (for example with Ctrl+C) can leave a partially written output file behind.** Your original is only deleted after a successful run, so it stays intact. Delete the partial file by hand before running again.
- **Files are not compatible** with the earlier Python version or with v1.0 build of this one.

## Download

Prebuilt binaries for Linux and Windows (x86-64) are on the [Releases](https://github.com/kyzenia/arc-yabgu/releases) page.

- Windows may show a SmartScreen or antivirus warning, because the executable is unsigned and the program encrypts and deletes files. Compare the SHA-256 checksum from the release notes with your download if you want to verify it.

## Build from source

You need a C compiler (GCC, Clang, or MinGW-w64 on Windows).

```sh
gcc -O2 -s -Wall -Wextra -o yabgu yabgu.c
```

Add `-static` if you want a binary that doesn't depend on the system's C library.

## Usage

Run the program from a terminal, ideally in the folder that contains your file:

```sh
./yabgu-linux-x86_64            # Linux
yabgu-windows-x86_64.exe        # Windows
```

The menu offers three choices:

```
1) Encrypt File
2) Decrypt File
3) Exit
```

Then you are asked for:

1. **The file's name.** A relative or full path works. The file must exist.
2. **A seed.** Any whole number from -9223372036854775808 to 9223372036854775807.
3. **A key.** Digits only (0-9). Longer keys are supported, up to the limit set by `MAX_KEY_DIGITS` in the source, currently 4000. Leading zeros count, so `007` and `7` are different keys.

### Example

```
$ ./yabgu-linux-x86_64
Your selection: 1
Enter your file's full name: README.md
Enter your seed (integer): 13526743148362
Enter your key (digits only): 219478420578

Encryption complete. Please check "README.md.yabgu"
```

To get the file back, choose `2`, enter `README.md.yabgu`, and use the same seed and key.

### File names

- Encrypting `name` creates `name.yabgu`.
- Decrypting only accepts files ending in `.yabgu`, and removes that suffix for the output name.
- Any file type works, since the file is processed as raw bytes in 8 MB chunks, so large files are fine.

## How it works

1. The seed drives a built-in 64-bit generator (splitmix64) that shuffles the byte values 0-255 into ten different substitution tables, one for each digit 0-9.
2. Each digit of the key picks a table. The key repeats along the file, so byte 0 uses the first digit, byte 1 the second, and so on, wrapping around at the end of the key.
3. Every byte is replaced with the value from its table. Decryption uses the inverse tables.

Because the tables are generated by Yabgu's own generator, the same seed and key give the same result on every platform and compiler.

## Security

Yabgu is a *polyalphabetic substitution cipher*. That has real limits:

- **Statistics survive.** Each byte maps to exactly one other byte, so patterns in the original data (text, source code, documents) show through, and can be attacked without knowing the seed or key.
- **Known plaintext helps an attacker.** Many file formats start with public headers, and knowing a few plaintext bytes reveals the tables.
- **No diffusion.** Changing one input byte changes only one output byte.
- **No authentication.** Nothing detects a wrong key or a modified file.
- **The generator is not cryptographically secure.** The tables come from a single 64-bit seed.

The large seed and key space protects against brute-forcing the key, but not against these structural weaknesses. If you need real protection, use a vetted tool such as [age](https://age-encryption.org), GnuPG, or a library like libsodium.
